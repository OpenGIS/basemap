# Build Pipeline

> How `scripts/build.sh` turns the vendored OpenMapTiles sources into the published artifacts.

## Overview

The build reproduces `make build-style` from OpenMapTiles v3.16 against the vendored sources, using the same docker tooling, then rewrites the result to point at the published URLs and merges the comma-joined font stacks.

Pipeline: **docker recompose → sprite generation → jq rewrite → publish to root → font merging → random screenshot**.

## 1. Docker recompose

[`scripts/build.sh`](../scripts/build.sh) runs the `openmaptiles/openmaptiles-tools:7.2` image with the project root mounted at `/tileset` and `vendor/openmaptiles/style` mounted at `/style`:

```bash
docker run --rm --user="$(id -u):$(id -g)" \
  -v "$ROOT":/tileset \
  -v "$ROOT/vendor/openmaptiles/style":/style \
  -w /tileset \
  openmaptiles/openmaptiles-tools:7.2 \
  bash -c 'style-tools recompose vendor/openmaptiles/openmaptiles.yaml build/style/style.json vendor/openmaptiles/style/style-header.json \
    && spreet /style/icons build/style/sprite \
    && spreet --retina /style/icons build/style/sprite@2x'
```

- `style-tools recompose` combines the 16 layer styles under `vendor/openmaptiles/layers/*/style.json` with the header (`vendor/openmaptiles/style/style-header.json`) into a single style at `build/style/style.json`.
- `spreet` builds the sprite sheets from the 306 SVGs in `vendor/openmaptiles/style/icons/` — `build/style/sprite` (plus `--retina` for `sprite@2x`).

## 2. jq rewrite

The recomposed style is rewritten with `jq` to point at the published URLs:

- `name` → `"Basemap"`
- `glyphs` → `https://www.ogis.org/basemap/fonts/{fontstack}/{range}.pbf`
- `sprite` → `https://www.ogis.org/basemap/sprite`
- `sources.openmaptiles.url` → `https://tiles.openfreemap.org/planet`
- `sources.attribution.attribution` → OpenFreeMap + © OpenMapTiles + Data from OpenStreetMap

> [!NOTE]
> URLs use **www.ogis.org** directly because the org's legacy `*.github.io` Pages host 301-redirects to it, and Chrome blocks cross-origin fetches that hit a redirect hop without a CORS header.

## 3. Publish to root

The final artifacts are copied to the repository root, which is what GitHub Pages serves:

- `style.json`
- `sprite.json`, `sprite.png`, `sprite@2x.json`, `sprite@2x.png`
- `icons/*.svg` (306 files)

`build/` itself is gitignored — only the root artifacts are committed.

## 4. Font merging

[`scripts/merge-fonts.js`](../scripts/merge-fonts.js) pre-merges the comma-joined `text-font` stacks from `style.json` into on-disk comma-named glyph directories under `fonts/`.

MapLibre GL requests glyphs with the `text-font` array joined by commas as the `{fontstack}` URL segment, e.g. `["Open Sans Semibold","Noto Sans Bold"]` → `fonts/Open Sans Semibold,Noto Sans Bold/0-255.pbf`. GitHub Pages is static, so those stacks must be pre-merged at build time:

- For each of the 256 glyph ranges, glyphs are merged across the stack's fonts — first font wins per glyph id, missing glyphs are filled from subsequent fonts (e.g. CJK flows from Noto Sans).
- Single-font stacks are served as-is.
- The script is zero-dependency: it implements a minimal reader/writer for the fontnik/Mapbox glyph PBF schema only.
- It is idempotent: merged directories are removed and rewritten on every run.

Result: 21 fontstack directories (10 single fonts + 11 merged stacks), 256 PBF ranges each, ~450 MB total.

## 5. Random screenshot

The build ends by running [`scripts/random-map.js`](../scripts/random-map.js), which renders a fresh random basemap to `screenshot.png` at the repo root (see [4.screenshots.md](4.screenshots.md)). It picks a random land point anywhere on Earth (Natural Earth 110m polygons, fetched on first run and cached at `build/land-110m.geojson`), then quality-gates the render — re-rolling up to 15 times until the harness's quality score clears the threshold, with zoom biased towards detail (70% of attempts zoom 12–14, 30% zoom 10–12). This artifact is intentionally non-deterministic — every build produces a different map — so the README screenshot stays fresh. The step fails loudly (exit code 1) if land data is unavailable or no render clears the threshold — the build fails rather than falling back to a curated render.

> [!NOTE]
> The build now needs network access on first run to fetch the land polygons (the tiles already need network). Subsequent runs use the cached copy in `build/` and work offline.

## Running the Build

```bash
./scripts/build.sh
```

Requires Docker, Node.js, and the Playwright tooling (`npm install` + `npx playwright install chromium`). The style artifacts (`style.json`, sprites, icons, fonts) are deterministic and idempotent — re-running the build reproduces them exactly. The one exception is `screenshot.png`, which is intentionally re-rendered as a random map on every build.
