# Remixing the Style

> How to modify the dark map theme, the icon palettes and the upstream cartography, then rebuild and republish both styles.

## Where to Edit

The distribution has three separate editing surfaces:

| Surface | Source | Controls |
| --- | --- | --- |
| Dark map theme | [`themes/dark/theme.json`](../themes/dark/theme.json) | Style-layer paint colours in the dark style |
| Icon palettes | [`palette.json`](../palette.json) (light) and [`themes/dark/palette.json`](../themes/dark/palette.json) (dark) | Fills baked into the POI SVGs |
| Upstream cartography | `vendor/openmaptiles/layers/*/style.json`, `vendor/openmaptiles/style/style-header.json` and `vendor/openmaptiles/style/icons/*.svg` | Layer definitions, publication defaults and icon artwork |

The map theme and the icon palettes are not interchangeable. The theme recolours style layers through ordered rules; the palettes recolour the primary fill of selected POI SVG icons before the sprites are built. Changing one does not change the other.

The light style is deliberately a cartographic no-op of the raw upstream recompose: it differs from `build/style/style.json` only in publication fields. To change light cartography, change the vendored layer styles (and reapply after a sync, because the mirror is replaced), or add a dedicated theme and build wiring. The dark style starts from the light clone and applies the dark theme strictly.

- **Layer styles**: `vendor/openmaptiles/layers/*/style.json` — one directory per OpenMapTiles layer.
- **Style header**: `vendor/openmaptiles/style/style-header.json` — name, centre, zoom, bearing, pitch, background layer and the source/glyphs/sprite defaults (the build overrides the publication fields).
- **Icon artwork**: `vendor/openmaptiles/style/icons/*.svg` — the source SVGs used to build the sprite sheets. Do not edit these to change palette colours; edit the appropriate icon palette instead. Edit the vendor SVG only when changing the artwork itself, and reapply that edit after a sync.

> [!NOTE]
> `vendor/openmaptiles/` is a pristine mirror of upstream `master`; `npm run upstream:sync` replaces it, so local changes to the mirror are not preserved. Provenance is in [`vendor/openmaptiles.lock.json`](../vendor/openmaptiles.lock.json), and [vendor/README.md](../vendor/README.md) documents the mirrored paths and sync commands. Syncing source does not rebuild the published styles — run `./scripts/build.sh` afterwards.

> [!NOTE]
> Icon colours are baked into the SVG `fill` values (including inline `style="fill:..."` overrides). The palette build recolours only each selected POI icon's primary fill from the active palette; inline style wins over the `fill` attribute, and white, preserved and non-primary details are untouched. The sprite is a raster PNG, not an SDF atlas, so `icon-color` and `icon-halo-*` have no effect. Preview changes in the [homepage palette inspector](https://www.ogis.org/basemap/) after deployment or in a local build, or see [5.palette.md](5.palette.md) and [6.site.md](6.site.md).

## Rebuild

```bash
./scripts/build.sh
```

The full build stages both palettes (`build/light/icons` and `build/dark/icons`), runs one Docker recompose, builds four sprites, generates `style.json` (dark, default) and `style-light.json`, publishes both sprite sets and icon trees, merges the fonts referenced by either style and assembles the static site in `.output/public`. See [2.build.md](2.build.md) for what happens in detail.

To stage one icon tree without building the map:

```bash
node scripts/palette.js --theme light --apply   # build/light/icons
node scripts/palette.js --theme dark --apply    # build/dark/icons
```

To preview palette changes without rebuilding, open the [homepage](https://www.ogis.org/basemap/) after the dual-style deployment, or use a local build, choose **Dark** or **Light**, turn on **Inspect POIs**, click a POI and edit its role colour. All icons in that role recolour live on the map; **Export palette** downloads the active palette as `palette.json`. Browser edits are live only:

- Copy a light export into the root [`palette.json`](../palette.json).
- Copy a dark export into [`themes/dark/palette.json`](../themes/dark/palette.json).

Then run the full build so the sprite and published icon tree are regenerated.

To rebuild only the site without regenerating the map artefacts:

```bash
npm run site:build
```

This regenerates `app/assets/data`, runs Nuxt generate, copies both styles and their assets into `.output/public` and validates the result. Use `npm run dev` for a live preview at <http://127.0.0.1:11100/basemap/>. Use this for app or palette-data changes; a palette colour change still needs the full build so the sprites and published icons are restaged. See [6.site.md](6.site.md).

## Republish

GitHub Actions deploys the site on a push to `master` ([`.github/workflows/pages.yml`](../.github/workflows/pages.yml)). Commit the regenerated map artefacts together:

- `style.json` and `style-light.json`
- both dark and light sprite sets
- `icons/` and `icons-light/`
- the generated palette data in `app/assets/data/`
- the refreshed homepage captures in `screenshots/`
- any changed app source

After an upstream sync, also commit the updated `vendor/openmaptiles/` mirror and `vendor/openmaptiles.lock.json`. Then push. The workflow runs the Node and Playwright test suites, verifies the upstream mirror, checks the generated data, builds `.output/public` and deploys it to Pages.

Generated site output is not committed: `.output/public` is gitignored and produced in the workflow.

> [!IMPORTANT]
> **Deploy both styles together.** The Pages artefact contains both styles, both sprite sets, both icon trees and the shared fonts. Publishing only part of `.output/public` leaves `style-light.json` or its assets unavailable.

> [!WARNING]
> **Keep the attribution** — the OpenFreeMap / © OpenMapTiles / OpenStreetMap attribution is a licence requirement (CC-BY-4.0 design, ODbL data). The build bakes it into both styles; don't remove it.

## Notes

- `build/` and `.output/` are gitignored intermediate output — never commit them.
- `icons/`, `icons-light/` and the sprite files are generated; edit the appropriate icon palette or the vendor layer/artwork sources instead.
- `app/assets/data/` is generated; edit the appropriate icon palette, then run `npm run palette:data`.
- Fonts are regenerated for every stack referenced by either `style.json` or `style-light.json`; the merge script derives the stack list from both styles' symbol layers.
- If you add a new font, place its PBF ranges in a directory under `fonts/` named after the font, and reference it from a layer's `text-font` array.
