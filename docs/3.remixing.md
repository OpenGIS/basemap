# Remixing the Style

> How to modify the style, rebuild the map artefacts and rebuild the site.

## Where to Edit

The style is defined by the vendored OpenMapTiles sources under `vendor/openmaptiles/`:

- **Layer styles**: `vendor/openmaptiles/layers/*/style.json` — the layer directories (aerodrome_label, aeroway, boundary, building, housenumber, landcover, landuse, mountain_peak, park, place, poi, transportation, transportation_name, water, water_name, waterway).
- **Style header**: `vendor/openmaptiles/style/style-header.json` — name, centre, zoom, bearing, pitch, background layer and the source/glyphs/sprite defaults (these are overridden by the build's jq rewrite).
- **Icons**: `vendor/openmaptiles/style/icons/*.svg` — the source SVGs used to build the sprite sheets. Do not edit these to change palette colours: the target palette is [`palette.json`](../palette.json), and the build recolours a staged copy in `build/icons`. Edit the vendor SVG only when changing the artwork itself.

> [!NOTE]
> Icon colours are baked into the SVG `fill` values (including inline `style="fill:..."` overrides). The palette build recolours only each selected POI icon's primary fill from `palette.json`; inline style wins over the `fill` attribute, and white, preserved and non-primary details are untouched. The sprite is a raster PNG, not an SDF atlas, so `icon-color` and `icon-halo-*` have no effect. Preview changes in the [homepage palette inspector](https://www.ogis.org/basemap/) or see [5.palette.md](5.palette.md) and [6.site.md](6.site.md).

## Rebuild

```bash
./scripts/build.sh
```

This applies `palette.json` — staging recoloured icons in `build/icons` — then regenerates `style.json`, the sprite sheets, `icons/`, the merged `fonts/` directories, the static site in `.output/public` and a fresh random `screenshots/random.jpg`. See [2.build.md](2.build.md) for what happens in detail.

To preview palette changes without rebuilding the map, open the [homepage](https://www.ogis.org/basemap/), turn on **Inspect POIs**, click a POI and edit its role colour. All icons in that role recolour live on the map; **Export palette** downloads the current colours as `palette.json`. Browser edits are live only — copy the exported colours into the root [`palette.json`](../palette.json) before rebuilding.

To rebuild only the site without regenerating the map artefacts:

```bash
npm run site:build
```

This regenerates `app/assets/data`, runs Nuxt generate, copies the root map artefacts into `.output/public` and validates the result. Use `npm run dev` for a live preview at <http://127.0.0.1:11100/basemap/>. Use this for app or palette-data changes; a palette colour change still needs the full build above so the sprite and published icons are restaged. See [6.site.md](6.site.md).

## Republish

GitHub Actions deploys the site on a push to `master` ([`.github/workflows/pages.yml`](../.github/workflows/pages.yml)). Commit the regenerated map artefacts (`style.json`, the sprite files, `icons/`), the generated palette data in `app/assets/data/`, the refreshed `screenshots/` captures and any changed app source, then push. The workflow runs the Node and Playwright test suites, checks the generated data, builds `.output/public` and deploys it to Pages.

Generated site output is not committed: `.output/public` is gitignored and produced in the workflow.

> [!WARNING]
> **Keep the attribution** — the OpenFreeMap / © OpenMapTiles / OpenStreetMap attribution is a licence requirement (CC-BY-4.0 design, ODbL data). The build bakes it in; don't remove it.

## Notes

- `build/` and `.output/` are gitignored intermediate output — never commit them.
- `icons/` and the sprite files are generated; edit `palette.json` or the vendor layer/artwork sources instead.
- `app/assets/data/` is generated; edit `palette.json`, then run `npm run palette:data`.
- Fonts are only regenerated for stacks actually referenced by `style.json`; the merge script derives the stack list from the style's symbol layers.
- If you add a new font, place its PBF ranges in a directory under `fonts/` named after the font, and reference it from a layer's `text-font` array.
