# Screenshot Pipeline

> How the homepage harness, the Playwright screenshot tools and the end-to-end tests work across the dark and light themes.

## Overview

Two pieces make up the screenshot pipeline:

- [`app/pages/index.vue`](../app/pages/index.vue) — the homepage is a full-screen MapLibre GL harness with a compact overlay, theme toggle and POI inspector. Camera state is encoded in the URL hash and render options in the query string, and the page exposes automation signals for headless capture. MapLibre GL is installed from npm and self-hosted in the site bundle.
- [`scripts/screenshot.js`](../scripts/screenshot.js) — a minimal Playwright capture tool that renders any state to a PNG or JPEG, with `--theme dark|light`.

The Playwright end-to-end suite also exercises the homepage, both themes and the inspector; see [End-to-end smoke tests](#end-to-end-smoke-tests).

The screenshot tools and the end-to-end test server serve the generated site in `.output/public` under the `/basemap/` base path, matching the deployed layout. Run `npm run site:build` before capturing or testing.

## Homepage State URL

The homepage reads its camera state from an OSM-style hash, matching www.ogis.app, and its rendering options from URL query parameters ([`app/pages/index.vue:379-418`](../app/pages/index.vue), [`app/utils/mapState.js`](../app/utils/mapState.js)):

```text
/basemap/#map=17/51.515400/-0.175500/0/0
/basemap/?theme=light&width=1200&height=630&quality=1#map=17/51.515400/-0.175500/0/0
```

The hash format is `#map=zoom/lat/lng/pitch/bearing`. The defaults open the homepage at London Paddington station (`51.5154, -0.1755`) at zoom 17, close enough that the default view includes POIs.

| Hash field | Meaning | Notes |
| --- | --- | --- |
| `zoom` | Zoom level | Any finite number |
| `lat` | Latitude in degrees | |
| `lng` | Longitude in degrees | |
| `pitch` | Pitch in degrees | |
| `bearing` | Bearing in degrees | Maps to MapLibre `bearing` |

A hash is accepted when it has exactly five numeric segments. When the page writes the camera back to the URL, latitude and longitude use six decimal places and zoom, pitch and bearing are rounded to integers ([`app/utils/mapState.js:33-51`](../app/utils/mapState.js)). An absent or invalid hash falls back to the legacy query parameters `lat`, `lng`, `zoom`, `pitch` and `rotation` ([`app/utils/mapState.js:53-69`](../app/utils/mapState.js)). Non-numeric values fall back to the defaults.

Rendering options remain query parameters:

| Param | Meaning | Default | Notes |
| --- | --- | --- | --- |
| `width` | Viewport width in px | fullscreen | Only applied together with `height`; clamped 100–4000 |
| `height` | Viewport height in px | fullscreen | Only applied together with `width`; clamped 100–4000 |
| `theme` | Site and map theme | `dark` | `dark` or `light`; selects the matching native style unless `style` is set |
| `style` | Style JSON URL | the theme's native style | Override for testing other styles; stays fixed when the site palette switches |
| `quality` | Enable render-quality scoring | off | A non-empty value (e.g. `quality=1`) enables it; sets `preserveDrawingBuffer: true` and reports `body[data-map-quality]` after `idle` |

Camera moves are written with `history.replaceState`, preserving the query string, on every `moveend`. A `hashchange` listener jumps the map to the new hash with `map.jumpTo` ([`app/pages/index.vue:435-462`](../app/pages/index.vue)).

The route is `/` within the site, served as `/basemap/`. The homepage is a Nuxt route, not a root `index.html`; the generated static site includes an `index.html` at the base path. The Nuxt page also keeps an `/index.html` alias for that generated entry point ([`app/pages/index.vue:23-25`](../app/pages/index.vue)).

### Live state overlay

The compact overlay (top-left) carries the Open GIS brand and logo, the `Basemap` title, a **Dark / Light** toggle, an **Inspect POIs** toggle, an **Export palette** button and a live readout ([`app/pages/index.vue:528-586`](../app/pages/index.vue)). The readout shows `lat, lng` (4 decimal places), `zoom` (1 dp) and `pitch`/`bearing` (integer degrees). It is initialised from the map after construction and re-rendered on every `move` event ([`app/pages/index.vue:423-433`](../app/pages/index.vue)). The readout uses the Open GIS theme tokens so it stays legible over the map.

The **Dark / Light** toggle changes the site token set and the map style together. It captures the camera before `map.setStyle`, restores it after the new style is idle, and applies the active palette's icons before marking the map ready again ([`app/pages/index.vue:307-377`](../app/pages/index.vue)). A `?style=` override is left in place while the site palette switches.

When **Inspect POIs** is active, clicking a POI opens the inspector (bottom-right). It shows the icon preview, POI name, class/subclass, layer, palette role, colour picker, hex field, role reset and close controls ([`app/pages/index.vue:588-677`](../app/pages/index.vue)). Editing a role recolours every icon in that role on the map; **Export palette** downloads the active palette's current colours as `palette.json`. See [6.site.md](6.site.md) for the inspector internals.

### Automation signals

For headless capture the harness sets three attributes on `<body>`:

- `body[data-map-ready]` — set once MapLibre fires `idle` and the initial palette images have been applied (map fully rendered). It is cleared and set again across a theme switch.
- `body[data-map-error]` — set on any MapLibre `error` event.
- `body[data-map-quality]` — set after `idle` when quality mode is on: the normalised luminance standard deviation (0–1, 4 dp) of the canvas downsampled to 32×32.

## Setup

```bash
npm ci        # or npm install — installs the Playwright dev dependencies
npx playwright install chromium
```

> [!NOTE]
> The screenshot tools and the end-to-end suite need the Playwright Chromium binary, which `npm install` does not download — run `npx playwright install chromium` once after installing. On Linux CI, `npx playwright install --with-deps chromium` also installs the system libraries.

## `npm run screenshot`

Captures a PNG or JPEG of the homepage for a given map state; the format follows the output extension. Run `npm run site:build` first. Pass flags after `--`:

```bash
npm run screenshot -- --lat 51.5074 --lng -0.1278 --zoom 12 --pitch 45 --rotation 20 --width 1200 --height 630 --out london.png
```

| Flag | Meaning | Default |
| --- | --- | --- |
| `--lat <n>` | Latitude in degrees | `51.5154` |
| `--lng <n>` | Longitude in degrees | `-0.1755` |
| `--zoom <n>` | Zoom level | `17` |
| `--pitch <n>` | Pitch in degrees | `0` |
| `--rotation <n>` | Bearing in degrees | `0` |
| `--width <n>` | Viewport width in px | `1200` |
| `--height <n>` | Viewport height in px | `630` |
| `--theme <name>` | Site and map theme: `dark` or `light` | `dark` |
| `--style <url>` | Style JSON URL; overrides the theme's style | the theme's native style |
| `--out <path>` | Output image path (`.jpg`/`.jpeg` uses JPEG quality 80) | `screenshots/home.png` |
| `--help` | Show usage | |

The tool writes the camera flags into `#map=zoom/lat/lng/pitch/bearing` and keeps `width`, `height`, `theme`, `style` and `quality` in the query string. Without `--style`, `--theme dark` selects `./style.json` and `--theme light` selects `./style-light.json`.

Examples:

```bash
# Defaults: London Paddington at 1200x630, dark
npm run screenshot

# Light theme and palette
npm run screenshot -- --theme light --out screenshots/home-light.png

# London at pitch 45, bearing 20
npm run screenshot -- --lat 51.5074 --lng -0.1278 --zoom 12 --pitch 45 --rotation 20

# Custom output path
npm run screenshot -- --lat 48.8566 --lng 2.3522 --zoom 13 --out paris.png
```

The native styles are rewritten before capture: the script reads `.output/public/style.json` or `.output/public/style-light.json`, replaces `sprite` with the absolute local URL for the matching sprite (`/basemap/sprite` or `/basemap/sprite-light`) and `glyphs` with `http://127.0.0.1:<port>/basemap/fonts/{fontstack}/{range}.pbf`, then writes `.output/public/screenshot-style.json` or `.output/public/screenshot-light-style.json` and passes it to the map ([`scripts/screenshot.js:38-108`](../scripts/screenshot.js)). The absolute sprite URL is required because MapLibre GL JS 6.5.0 rejects relative sprite URLs. Custom `--style` values are not rewritten and must be reachable from the browser. The generated files live in the gitignored `.output/public`, so they are never committed and are removed after each run.

## End-to-end smoke tests

`npm test` runs the Node suite only. The Playwright suite in [`tests/e2e/smoke.spec.js`](../tests/e2e/smoke.spec.js) exercises the built site:

```bash
npm run test:e2e:build   # npm run site:build, then playwright test
npm run test:e2e         # playwright test against an existing .output/public
```

[`playwright.config.js`](../playwright.config.js) starts [`scripts/test-server.js`](../scripts/test-server.js), which serves `.output/public` at <http://127.0.0.1:11101/basemap/>. The viewport is fixed at 1200x630 and failures retain a trace. The server serves the localised native and screenshot styles in memory, so requests for `/basemap/style.json`, `/basemap/style-light.json`, `/basemap/screenshot-style.json` and `/basemap/screenshot-light-style.json` return documents whose sprite and glyph URLs point at the local server ([`scripts/test-server.js:43-50`](../scripts/test-server.js)). Other assets, including fonts and icons, are served from the built artefact.

The suite covers:

- **Dark default** — loads the map without a theme parameter, asserts the `Basemap — Open GIS` title, waits for `body[data-map-ready]`, checks the dark tokens, the native dark style request, the themed MapLibre controls, the canvas and the state readout, asserts zero console and page errors, and writes `screenshots/home.png`.
- **Explicit light theme** — loads with `?theme=light`, checks the light tokens, the native light style request and the themed controls, and writes `screenshots/home-light.png`.
- **Theme toggle** — selects a POI, switches between dark and light, and verifies that the camera hash is preserved, the inspector is cleared, the map readiness signal cycles and the matching native style is requested.
- **Style override** — loads with `?style=` and verifies that the override stays fixed while the site palette switches between dark and light.
- **Inspector recolour and export** — for each palette, enables **Inspect POIs**, clicks a POI, checks the inspector and Health role, changes the hex colour, verifies the map pixels change, exports the palette and checks the exported role colour. Temporary inspector captures are scratch files and are not committed.

`screenshots/home.png` and `screenshots/home-light.png` are committed outputs; `screenshots/` is not a temporary or ignored directory. Review and commit the refreshed captures when a run changes them. The inspector captures are scratch files and are not committed.

## How It Works

`scripts/screenshot.js` exports `capture(opts)`:

1. **Throwaway static server** — Chromium blocks `file://` fetches of `style.json`, so the script serves the generated site in `.output/public` over a tiny Node `http` + `fs` server on an ephemeral `127.0.0.1` port. The shared [`scripts/lib/site-server.js`](../scripts/lib/site-server.js) handles the HTTP layer; request-to-file mapping stays in [`scripts/site-build.js`](../scripts/site-build.js). Requests must live under `/basemap/`; the prefix is stripped to map onto the artefact directory.
2. **Load the homepage** — opens `/basemap/index.html` with `width`, `height`, `theme` and `style` in the query string and camera state in the `#map=` hash.
3. **Wait for ready** — waits for `body[data-map-ready]` (60s timeout); if `body[data-map-error]` appears it fails with a clear message about the style URL / network access.
4. **Quality mode (optional)** — with `quality: true` the URL gets `quality=1`, the harness reports `body[data-map-quality]` after `idle`, and `capture()` waits for it (10s timeout).
5. **Settle and shoot** — waits 750ms for tiles and labels to finish, then screenshots.

`capture()` returns `{ url, out, format, quality, theme }` — `format` is `png` or `jpeg`, `quality` is the numeric score when quality mode was requested (`null` otherwise), and `theme` is the resolved theme. If `.output/public/index.html` is missing, it fails with a message to run `npm run site:build`.
