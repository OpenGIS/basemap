# Screenshot Pipeline

> How the state-driven demo page, the Playwright screenshot tools and the end-to-end smoke tests work.

## Overview

Three pieces make up the screenshot pipeline:

- [`app/pages/index.vue`](../app/pages/index.vue) — the demo page is a state-driven MapLibre GL harness: every map state (centre, zoom, pitch, bearing, viewport size) is encoded in the URL query string, and it exposes automation signals for headless capture. MapLibre GL is installed from npm and self-hosted in the site bundle.
- [`scripts/screenshot.js`](../scripts/screenshot.js) — a minimal Playwright capture tool that renders any state to a PNG.
- [`scripts/random-map.js`](../scripts/random-map.js) — picks a random land point anywhere on Earth (quality-gated) and renders the README screenshot.

The Playwright end-to-end suite also captures the demo and palette pages; see [End-to-end smoke tests](#end-to-end-smoke-tests).

The screenshot tools and the end-to-end test server serve the generated site in `.output/public` under the `/basemap/` base path, matching the deployed layout. Run `npm run site:build` before capturing or testing; [`scripts/build.sh`](../scripts/build.sh) does this automatically before its random screenshot.

## Demo Page State URL

The demo page reads its initial map state from URL query parameters ([`app/pages/index.vue:19-34`](../app/pages/index.vue)):

| Param | Meaning | Default | Notes |
| --- | --- | --- | --- |
| `lat` | Latitude in degrees | `0` | |
| `lng` | Longitude in degrees | `20` | |
| `zoom` | Zoom level | `2` | |
| `pitch` | Pitch in degrees | `0` | |
| `rotation` | Bearing in degrees | `0` | Maps to MapLibre `bearing` |
| `width` | Viewport width in px | fullscreen | Only applied together with `height`; clamped 100–4000 |
| `height` | Viewport height in px | fullscreen | Only applied together with `width`; clamped 100–4000 |
| `style` | Style JSON URL | `./style.json` | Override for testing other styles |
| `quality` | Enable render-quality scoring | off | A non-empty value (e.g. `quality=1`) enables it; sets `preserveDrawingBuffer: true` and reports `body[data-map-quality]` after `idle` |

Non-numeric values fall back to the defaults; `width`/`height` are rounded and clamped to 100–4000. If only one of `width`/`height` is given, the map stays fullscreen.

The route is `/` within the site, served as `/basemap/`. The demo is a Nuxt route, not a root `index.html`; the generated static site includes an `index.html` at the base path. The Nuxt page also keeps an `/index.html` alias for that generated entry point ([`app/pages/index.vue:5-7`](../app/pages/index.vue)).

### Live state overlay

A live readout (top-left) shows `lat, lng` (4 decimal places), `zoom` (1 dp) and `pitch`/`bearing` (integer degrees). It is initialised from the map after construction and re-rendered on every `move` event ([`app/pages/index.vue:58-68`](../app/pages/index.vue)). The readout uses dark text (`#18281a`) on a translucent light panel so it stays legible over the map.

### Automation signals

For headless capture the harness sets three attributes on `<body>`:

- `body[data-map-ready]` — set once MapLibre fires `idle` (map fully rendered).
- `body[data-map-error]` — set on any MapLibre `error` event.
- `body[data-map-quality]` — set after `idle` when quality mode is on: the normalised luminance standard deviation (0–1, 4 dp) of the canvas downsampled to 32×32.

## Setup

```bash
npm ci        # or npm install — installs the Playwright dev dependencies
npx playwright install chromium
```

> [!NOTE]
> The screenshot tools and the end-to-end suite need the Playwright Chromium binary, which `npm install` does not download — run `npx playwright install chromium` once after installing. On Linux CI, `npx playwright install --with-deps chromium` also installs the system libraries.

## `npm run screenshot`

Captures a PNG or JPEG of the demo page for a given map state; the format follows the output extension. Run `npm run site:build` first. Pass flags after `--`:

```bash
npm run screenshot -- --lat 51.5074 --lng -0.1278 --zoom 12 --pitch 45 --rotation 20 --width 1200 --height 630 --out london.png
```

| Flag | Meaning | Default |
| --- | --- | --- |
| `--lat <n>` | Latitude in degrees | `0` |
| `--lng <n>` | Longitude in degrees | `20` |
| `--zoom <n>` | Zoom level | `2` |
| `--pitch <n>` | Pitch in degrees | `0` |
| `--rotation <n>` | Bearing in degrees | `0` |
| `--width <n>` | Viewport width in px | `1200` |
| `--height <n>` | Viewport height in px | `630` |
| `--style <url>` | Style JSON URL | `./style.json` |
| `--out <path>` | Output image path (`.jpg`/`.jpeg` uses JPEG quality 80) | `screenshots/home.png` |
| `--help` | Show usage | |

The default `screenshots/home.png` path is the same demo capture that the end-to-end suite refreshes.

Examples:

```bash
# Defaults: world view at 1200x630
npm run screenshot

# London at pitch 45, bearing 20
npm run screenshot -- --lat 51.5074 --lng -0.1278 --zoom 12 --pitch 45 --rotation 20

# Custom output path
npm run screenshot -- --lat 48.8566 --lng 2.3522 --zoom 13 --out paris.png
```

The default `./style.json` resolves relative to the `/basemap/` page, so it loads the copied map artefact from the site build. A custom `--style` URL must be reachable from the browser.

## `npm run screenshot:random`

Renders a random, nice-looking map to `screenshots/random.jpg` (fixed 1200x630):

- **Random land point anywhere on Earth** — Natural Earth 110m land polygons are fetched once from GitHub and cached at `build/land-110m.geojson` (gitignored; subsequent runs work offline). Land checks use a zero-dependency point-in-polygon test (ray casting with a bounding-box pre-check).
- **Random state per attempt** — uniform lat [-85, 85] / lng [-180, 180] on land, pitch 0–60, rotation 0–359. Zoom is biased towards detail: 70% of attempts zoom 12–14, 30% zoom 10–12 (1 dp).
- **Quality gate** — each render is captured in quality mode and scored by the harness (normalised luminance stddev of the 32×32 downsampled canvas). Attempts re-roll up to 15 times until the score clears `QUALITY_THRESHOLD` (0.03, tuned empirically: boring tundra/Sahara/ocean scenes score below, textured scenes like Matterhorn, London or the Grand Canyon score above).
- **Fails loudly** — if land data is unavailable (no cache and the fetch failed) or all 15 attempts fall below the threshold, the script throws and exits with code 1. There is no fallback: the build fails rather than produce a curated render.
- Prints coords, zoom, pitch, rotation, and quality (always present).

```bash
npm run screenshot:random                 # writes screenshots/random.jpg
npm run screenshot:random -- --out tmp.png
```

This is the script the build runs to regenerate the README screenshot.

## End-to-end smoke tests

`npm test` runs the Node suite only. The Playwright suite in [`tests/e2e/smoke.spec.js`](../tests/e2e/smoke.spec.js) exercises the built site:

```bash
npm run test:e2e:build   # npm run site:build, then playwright test
npm run test:e2e         # playwright test against an existing .output/public
```

[`playwright.config.js`](../playwright.config.js) starts [`scripts/test-server.js`](../scripts/test-server.js), which serves `.output/public` at <http://127.0.0.1:11101/basemap/>. The viewport is fixed at 1200x630 and failures retain a trace. The suite loads the demo and palette routes, waits for the demo map to become ready, asserts zero console and page errors, checks the state readout and palette summary, and writes `screenshots/home.png` and `screenshots/palette.png`.

Those captures and `screenshots/random.jpg` are committed outputs; `screenshots/` is not a temporary or ignored directory. Review and commit the refreshed images when a run changes them.

## How It Works

`scripts/screenshot.js` exports `capture(opts)` (reused by `random-map.js`):

1. **Throwaway static server** — Chromium blocks `file://` fetches of `style.json`, so the script serves the generated site in `.output/public` over a tiny Node `http` + `fs` server on an ephemeral `127.0.0.1` port. The shared [`scripts/lib/site-server.js`](../scripts/lib/site-server.js) handles the HTTP layer; request-to-file mapping stays in [`scripts/site-build.js`](../scripts/site-build.js). Requests must live under `/basemap/`; the prefix is stripped to map onto the artefact directory.
2. **Load the demo page** — opens `/basemap/index.html` with the state encoded in the query string.
3. **Wait for ready** — waits for `body[data-map-ready]` (60s timeout); if `body[data-map-error]` appears it fails with a clear message about the style URL / network access.
4. **Quality mode (optional)** — with `quality: true` the URL gets `quality=1`, the harness reports `body[data-map-quality]` after `idle`, and `capture()` waits for it (10s timeout).
5. **Settle and shoot** — waits 750ms for tiles and labels to finish, then screenshots.

`capture()` returns `{ url, out, format, quality }` — `format` is `png` or `jpeg`, and `quality` is the numeric score when quality mode was requested, `null` otherwise. If `.output/public/index.html` is missing, it fails with a message to run `npm run site:build`.
