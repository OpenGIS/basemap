# Site and Palette Inspector

> How the single Nuxt site serves the dark-first full-screen basemap and live palette inspector, and how its palette data and Pages artefact are produced.

## Overview

The repository is one root Nuxt 4.3.1 project. It publishes one consumer-facing route under the base path `/basemap/`:

| Route | Source | Purpose |
| --- | --- | --- |
| `/` | [`app/pages/index.vue`](../app/pages/index.vue) | Full-screen MapLibre basemap with the Open GIS overlay, theme toggle and POI palette inspector |

The route is client-only: `ssr: false` disables server rendering ([`nuxt.config.mjs:9`](../nuxt.config.mjs)). Nuxt writes build assets to `nuxt-assets/` rather than the default `/_nuxt/` ([`nuxt.config.mjs:15`](../nuxt.config.mjs)), and MapLibre GL is installed from npm and self-hosted in the site bundle ([`package.json`](../package.json), [`app/pages/index.vue:2-3`](../app/pages/index.vue)). The page title is `Basemap — Open GIS` ([`app/pages/index.vue:30-32`](../app/pages/index.vue)); the Nuxt head supplies the `en-GB` language, a dark default via `htmlAttrs['data-theme']`, a description naming a basemap with a live palette inspector, the colour scheme and the favicon ([`nuxt.config.mjs:16-40`](../nuxt.config.mjs)).

The development server binds to `127.0.0.1` and runs on port 11100 ([`nuxt.config.mjs:43-45`](../nuxt.config.mjs), [`package.json:6`](../package.json)). A dev-only Vite middleware serves the root `style.json` and `style-light.json` at `/basemap/style.json` and `/basemap/style-light.json` ([`nuxt.config.mjs:58-88`](../nuxt.config.mjs)), so the homepage can load either local style without running a site build first.

## The Nuxt app

- [`app/app.vue`](../app/app.vue) is the shell and renders `<NuxtPage />`.
- [`app/pages/index.vue`](../app/pages/index.vue) is the homepage: a full-screen MapLibre map, the overlay, the theme toggle, the POI inspector and the live role-colour updates.
- [`app/utils/mapState.js`](../app/utils/mapState.js) parses and formats the camera hash and provides the legacy query fallback.
- [`app/utils/mapFeatures.js`](../app/utils/mapFeatures.js) resolves a clicked map feature to its palette icon, class and role.
- [`app/utils/svgImage.js`](../app/utils/svgImage.js) rasterises a recoloured SVG template to `ImageData` at the map image's exact pixel size.
- [`app/utils/colour.js`](../app/utils/colour.js) normalises hex values, substitutes `__PALETTE_ROLE__` and builds the exported palette document.
- [`app/assets/data/`](../app/assets/data/) holds generated palette data. Do not hand-edit it; regenerate it with `npm run palette:data`.
- [`app/assets/scss/_tokens.scss`](../app/assets/scss/_tokens.scss) holds the dark-first Open GIS design tokens; the dark set is the default and light is an explicit `data-theme="light"` override.
- [`app/assets/scss/_home.scss`](../app/assets/scss/_home.scss) holds the homepage overlay, inspector and themed MapLibre control styles.
- [`app/assets/branding/`](../app/assets/branding/) and [`public/branding/`](../public/branding/) hold build-time and static branding assets.

## Overlay and inspector

The homepage renders the map full-screen behind a fixed, pointer-transparent overlay; the brand panel and inspector re-enable pointer events so they stay interactive over the map ([`app/assets/scss/_home.scss`](../app/assets/scss/_home.scss)).

The brand panel carries the Open GIS logo and wordmark, the `Basemap` title, a short description, the **Dark / Light** toggle, the **Inspect POIs** toggle, the **Export palette** button and the live camera readout ([`app/pages/index.vue:528-586`](../app/pages/index.vue)). The readout shows centre latitude/longitude, zoom, pitch and bearing and is updated on every `move`.

The **Dark / Light** toggle applies the matching `data-theme` to the document, swaps the map style and applies the active palette's icons. It captures the camera before `map.setStyle`, restores it once the new style is idle and again after the palette images are applied, so switching themes does not move the map ([`app/pages/index.vue:340-377`](../app/pages/index.vue)). When the page was opened with a `?style=` override, the override stays fixed and only the site tokens and palette switch. The `?theme=light|dark` query sets the initial theme and defaults to dark ([`app/pages/index.vue:379-397`](../app/pages/index.vue)).

**Inspect POIs** is a pressed-state toggle. Turning it on sets a crosshair cursor; turning it off closes the inspector ([`app/pages/index.vue:264-270`](../app/pages/index.vue)). While it is active, a map click queries rendered features on the non-text palette layers and resolves the first matching feature through [`resolveFeature`](../app/utils/mapFeatures.js) (`:41`). That helper evaluates the layer's `icon-image` expression — subclass, class, literal or `coalesce` — finds the icon in the generated palette data and returns its role, class, layer and display name. If no palette POI is found, the overlay shows a short hint.

The inspector shows:

- an icon preview rendered from the generated SVG template with the active palette's role colour;
- the POI name (falling back to the icon name) and its subclass/class;
- the map layer and palette role;
- a colour picker, a hex field and a **Reset role** button;
- a close control, plus a selection marker on the map.

Editing the colour validates the hex with [`normaliseHex`](../app/utils/colour.js) (`:5`), stores the new colour against the role in the active palette and applies it to every icon in that role. **Reset role** restores the colour from the generated data for the active palette.

### Export and persistence

**Export palette** builds a palette document from the active palette source and its current role colours, then downloads it as `palette.json` ([`app/pages/index.vue:293-305`](../app/pages/index.vue), [`buildPaletteDocument`](../app/utils/colour.js) (`:33`)). The document preserves the source structure — roles, `sourceColors`, `preserve` and `overrides` — while replacing each role's `color` with the live value.

Browser edits are live only. Nothing is written to disk or sent to a server, and a reload restores the generated colours. To persist a change, replace the matching source with the exported document and run the map build:

- light export → root [`palette.json`](../palette.json)
- dark export → [`themes/dark/palette.json`](../themes/dark/palette.json)

Then run `./scripts/build.sh`, which stages both icon trees, rebuilds both styles and sprites, publishes both icon sets and finishes with the site build. Use `npm run site:build` when only the app data or site code changed. See [5.palette.md](5.palette.md) and [2.build.md](2.build.md).

## Hash camera state

Camera state uses the OSM-style hash `#map=zoom/lat/lng/pitch/bearing`, matching www.ogis.app. The defaults are London Paddington (`51.5154, -0.1755`) at zoom 17 ([`app/utils/mapState.js:1-7`](../app/utils/mapState.js)).

- [`parseMapHash`](../app/utils/mapState.js) (`:16`) accepts exactly five numeric segments.
- [`formatMapHash`](../app/utils/mapState.js) (`:33`) writes latitude/longitude with six decimals and rounds zoom, pitch and bearing to integers.
- [`readMapState`](../app/utils/mapState.js) (`:53`) prefers a valid hash and falls back to the legacy `lat`, `lng`, `zoom`, `pitch` and `rotation` query parameters when the hash is absent or invalid.

On `moveend`, the page writes the current camera back to the hash with `history.replaceState`, preserving the query string. A `hashchange` listener jumps the map to the new state ([`app/pages/index.vue:435-462`](../app/pages/index.vue)). Query parameters remain for `width`, `height`, `theme`, `style` and `quality`; see [4.screenshots.md](4.screenshots.md) for the full URL API.

## Palette data flow

There are two editable icon palette sources: the root [`palette.json`](../palette.json) (light) and [`themes/dark/palette.json`](../themes/dark/palette.json) (dark). The dark map theme ([`themes/dark/theme.json`](../themes/dark/theme.json)) is separate: it controls style-layer colours, not icon fills. The homepage consumes both palettes and switches between them with the site theme.

1. **Model.** [`scripts/lib/palette.js`](../scripts/lib/palette.js) builds the light palette model from `palette.json`, the vendored POI schema, mapping and style, `sprite.json` and the source SVGs (`buildModel` at [`scripts/lib/palette.js:491`](../scripts/lib/palette.js)). It resolves each icon's primary fill to a role through `sourceColors`, then applies `overrides` ([`scripts/lib/palette.js:721-777`](../scripts/lib/palette.js)). `buildAppData` builds a second model from `themes/dark/palette.json`.
2. **App data.** [`scripts/palette-data.js`](../scripts/palette-data.js) serialises the models into [`app/assets/data/`](../app/assets/data/) ([`scripts/palette-data.js:412`](../scripts/palette-data.js)):
   - `palette.json` — top-level light data (roles with their icons and classes, the source palette document, missing names, phantoms, layers and summary) plus `themes.dark.palette` and `themes.dark.colours` ([`scripts/palette-data.js:442-452`](../scripts/palette-data.js)).
   - `icons.json` — one SVG template per POI icon, with the primary fill replaced by the `__PALETTE_ROLE__` placeholder.
   - `manifest.json` — the inputs hash and file hashes.

   Generation is deterministic. The inputs hash covers `palette.json`, `themes/dark/palette.json`, the palette/recolour/data-generator scripts, the POI schema and style files, `sprite.json` and every source SVG ([`scripts/palette-data.js:83-97`](../scripts/palette-data.js)). `--check` rebuilds the expected data in memory and reports missing or stale files ([`scripts/palette-data.js:506-541`](../scripts/palette-data.js)).

   Icon templates are built by recolouring each primary fill to a sentinel colour, then replacing the sentinel with `__PALETTE_ROLE__` ([`scripts/palette-data.js:355-410`](../scripts/palette-data.js)). The generator rejects source SVGs that already contain the sentinel or placeholder, so the template substitution is unambiguous.
3. **Runtime.** The homepage imports the generated data. It builds reactive `roleColours` maps for both palettes, uses [`iconDataUri`](../app/utils/colour.js) (`:23`) for the inspector preview, and uses each role's `iconNames` to recolour the map images live when the active palette changes. Only the placeholder is replaced; white, preserved and non-primary details stay as they are in the template.

`npm run palette:data` writes the data and `npm run palette:data:check` verifies it is in sync. Both derive the expected data from the light palette and the dark icon palette; `--check` then compares it with the generated copies.

## Icon recolour mechanism

MapLibre renders POI icons from the sprite as named images. The generated `icons.json` holds the matching SVG templates, so a role change does not need a new sprite build: the page rewrites the in-memory images and repaints.

For each icon in the edited role, [`updateMapImage`](../app/pages/index.vue) (`:130-154`) applies:

1. Normalises the role hex and checks that the map still has an image and a template for that icon.
2. Reads the current image's exact `data.width` and `data.height` from `map.getImage(name)`.
3. Substitutes every `__PALETTE_ROLE__` placeholder in the SVG template with the hex.
4. Rasterises the SVG to `ImageData` at those exact dimensions with [`svgToImageData`](../app/utils/svgImage.js) (`:10`), which draws the SVG onto a canvas and reads the pixels back.
5. Calls `map.updateImage(name, imageData)` and, once the role's icons are queued and applied, `map.triggerRepaint()`.

Image updates are serialised through a promise queue so rapid colour changes cannot interleave, and `applyRoleImages` only repaints after all icons in the role have been replaced ([`app/pages/index.vue:156-188`](../app/pages/index.vue)). Exact dimensions matter: `updateImage` replaces the sprite frame with the supplied pixels, so reusing the original width and height avoids resampling and keeps icons aligned with their rendered size.

On the first `idle`, `applyAllImages` applies the active palette's current colours to its icons before setting `body[data-map-ready]` ([`app/pages/index.vue:161-173`](../app/pages/index.vue), [`app/pages/index.vue:464-498`](../app/pages/index.vue)). The same path runs after a theme switch, so the rendered images match the active palette even when the sprite already matches the committed role colours.

### Themed MapLibre controls

MapLibre renders its zoom/compass control and attribution outside the overlay, so [`_home.scss`](../app/assets/scss/_home.scss) themes them globally through the site tokens ([`app/assets/scss/_home.scss:397-480`](../app/assets/scss/_home.scss)). The control group, buttons, separators and attribution surface use `--ogis-surface`, `--ogis-fg`, `--ogis-border` and `--ogis-accent`; the dark default inverts the icon bitmaps, while the light override leaves them untouched. The end-to-end suite checks the computed colours in both themes.

## Map data

The map data stays at the repository root, where the map build writes it:

- `style.json` (dark, default) and `style-light.json`
- `sprite.json`, `sprite.png`, `sprite@2x.json`, `sprite@2x.png`
- `sprite-light.json`, `sprite-light.png`, `sprite-light@2x.json`, `sprite-light@2x.png`
- `icons/` (dark) and `icons-light/` (light)
- `fonts/` (shared)

These are committed artefacts produced by [`scripts/build.sh`](../scripts/build.sh) (see [2.build.md](2.build.md)). They are not duplicated inside `app/`.

## Site build

[`scripts/site-build.js`](../scripts/site-build.js) assembles the deployable site in `.output/public`:

1. Regenerates `app/assets/data` with `scripts/palette-data.js`.
2. Runs `npm run generate` (`nuxt generate`).
3. Copies both styles, both sprite sets, both icon directories, the shared fonts and the MapLibre worker files into `.output/public` ([`scripts/site-build.js:411-446`](../scripts/site-build.js)).
4. Validates the generated `index.html`, local asset paths under `/basemap/`, both style documents, both sprite sets, both icon directories, the shared fonts, the MapLibre worker files and the absence of `_nuxt`/`_payload.json` references ([`scripts/site-build.js:280-346`](../scripts/site-build.js)). It also requires `style.json` to be the dark default and `style-light.json` to be the light style.

The page list contains only `index.html` ([`scripts/site-build.js:27`](../scripts/site-build.js)); the site has no second page to validate. `.output/public` is generated and gitignored. It is never committed; the Pages workflow uploads it as the deployment artefact.

## Local workflow

```bash
npm install
npx playwright install chromium   # screenshots and end-to-end tests
npm run dev
```

`npm run dev` serves the homepage at <http://127.0.0.1:11100/basemap/>.

`npm test` runs the Node suite. `npm run test:e2e:build` builds `.output/public` and runs the Playwright smoke suite; `npm run test:e2e` reuses an existing build. The test server serves the built site at <http://127.0.0.1:11101/basemap/> with a 1200x630 viewport (see [4.screenshots.md](4.screenshots.md)).

After editing either icon palette (`palette.json` or `themes/dark/palette.json`), regenerate the data the homepage imports:

```bash
npm run palette:data
npm run palette:data:check
```

To produce the complete deployable site locally:

```bash
npm run site:build
```

This writes `.output/public`, including the Nuxt homepage, the generated palette data and both styles with their sprite and icon sets. `npm run site:generate` runs only `nuxt generate`; `npm run site:build` is the full artefact build. The screenshot tools and the end-to-end suite require the `.output/public` build, so run `npm run site:build` before `npm run screenshot` or `npm run test:e2e` (see [4.screenshots.md](4.screenshots.md)). For native styles, the screenshot tools rewrite `sprite` and `glyphs` to absolute local URLs in generated `.output/public/screenshot-style.json` and `screenshot-light-style.json`, because MapLibre GL JS 6.5.0 rejects relative sprite URLs.

## Deployment

[`.github/workflows/pages.yml`](../.github/workflows/pages.yml) deploys only the consumer-facing homepage. It runs on pushes to `master` and on manual dispatch. The workflow:

1. Installs dependencies with `npm ci`.
2. Runs `npm test`.
3. Runs `npm run upstream:verify`.
4. Runs `npm run palette:data:check`.
5. Runs `npm run site:build`.
6. Installs Chromium with `npx playwright install --with-deps chromium`.
7. Runs `npm run test:e2e`.
8. Uploads `.output/public` as the Pages artefact and deploys it.

Both suites must pass before the upload; an end-to-end failure blocks deployment because the deploy job depends on the build job.

> [!IMPORTANT]
> **Deploy both styles together.** The live site serves Basemap Dark as the default at `/basemap/style.json` and Basemap Light at `/basemap/style-light.json`, with both sprite sets, `icons/`, `icons-light/` and the shared fonts. A rebuild must deploy the whole `.output/public`; the Pages workflow does this.

> [!IMPORTANT]
> In the repository's GitHub Pages settings, set **Source** to **GitHub Actions** once. The workflow uploads `.output/public`; there is no `gh-pages` branch and no generated site output in the repository.

The technical documentation under `docs/` is repository-only. It is not part of `.output/public` and is not published to Pages.

## CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on pull requests. It installs dependencies, runs `npm test`, runs `npm run upstream:verify`, checks the generated palette data with `npm run palette:data:check`, runs `npm run site:build`, installs Chromium with `npx playwright install --with-deps chromium`, and runs `npm run test:e2e`.

The Pages workflow repeats the Node suite, upstream verification, data check, site build, Chromium install and end-to-end suite on `master` pushes before deploying. Neither workflow builds the map with Docker; the map artefacts are committed and the site build copies them. Both workflows install Chromium for the end-to-end suite.

## Tests and attribution

`npm test` runs the Node test suite with `node --test`. It covers the palette model and recolouring, generated palette data, the theme engine, style generation and validation, the homepage's colour, map-state and map-feature helpers, font merging, the screenshot harness and site-build validation. It does not launch a browser.

`npm run test:e2e` runs the Playwright smoke suite against `.output/public`, served by `scripts/test-server.js` at <http://127.0.0.1:11101/basemap/> with a 1200x630 viewport. `npm run test:e2e:build` runs `npm run site:build` first. The suite covers the dark default, the explicit light theme, the theme toggle's camera preservation and map-readiness cycle, the fixed `?style=` override, the themed MapLibre controls and the inspector's recolour and export flow in both palettes, without console or page errors. It refreshes the committed `screenshots/home.png` and `screenshots/home-light.png` captures and writes temporary inspector captures to a gitignored scratch directory. It requires Chromium (`npx playwright install chromium`).

The site includes work from Open GIS branding, OpenMapTiles and OpenStreetMap. The dark map theme and dark POI icon palette derive from the Open GIS branding palette and design tokens.
