# Basemap

> A dark-first, self-hosted MapLibre GL basemap: the OpenMapTiles "OSM" vector style repointed at OpenFreeMap's worldwide vector tiles, with dark and light styles, sprites, icons and shared fonts served from GitHub Pages.

> [!IMPORTANT]
> **Both styles ship together** — the live site serves Basemap Dark as the default at `/basemap/style.json` and Basemap Light at `/basemap/style-light.json`, with both sprite sets, `icons/`, `icons-light/` and the shared `fonts/`. A rebuild must deploy the whole `.output/public`; the Pages workflow does this.

> [!NOTE]
> **Canonical host is www.ogis.org** — never use the org's legacy `*.github.io` Pages host. It 301-redirects to www.ogis.org, and the redirect hop breaks CORS in browsers, so every published URL points at www.ogis.org directly.

## Overview

Basemap vendors the OpenMapTiles "OSM" vector style (the vector equivalent of the official openstreetmap-carto raster) and repoints it at OpenFreeMap's worldwide, free OpenMapTiles-schema vector tiles. It publishes two styles from one upstream recompose: **Basemap Dark** at the root `style.json` (the default) and **Basemap Light** at `style-light.json`. Light is a cartographic no-op of the raw recompose; dark starts from that light clone and applies a strict, ordered theme derived from the Open GIS branding palette. Each style has its own sprite set and icon tree, while the merged font stacks are shared.

The repository is one root Nuxt site. Its only consumer-facing route is `/` — a full-screen MapLibre basemap at London Paddington (zoom 17) with a compact Open GIS overlay. The site opens dark by default and carries a **Dark / Light** toggle that swaps the site tokens and the map style together, preserving the camera. The overlay also carries the live camera readout, an **Inspect POIs** toggle and an **Export palette** button. Inspecting a POI opens an inspector with its icon, name, class/subclass, layer and palette role; editing the role colour recolours every icon in that role live on the map. The inspector edits the active theme's palette, and **Export palette** downloads its current colours as `palette.json`. Browser edits are live only — to make them permanent, update the appropriate palette source and rebuild.

The map artefacts are built from vendored upstream sources with the same docker tooling OpenMapTiles uses (`openmaptiles-tools:7.2`), then rewritten to point at the published URLs. See [docs/2.build.md](docs/2.build.md) for the pipeline and [docs/7.themes.md](docs/7.themes.md) for the theme system.

## Usage

### Dark (default)

```js
const map = new maplibregl.Map({
  container: "map",
  style: "https://www.ogis.org/basemap/style.json",
});
```

### Light

```js
// Light
const map = new maplibregl.Map({
  container: "map",
  style: "https://www.ogis.org/basemap/style-light.json",
});
```

### Assets in a custom style

```json
{
  "version": 8,
  "sources": {
    "openmaptiles": {
      "type": "vector",
      "url": "https://tiles.openfreemap.org/planet"
    }
  },
  "glyphs": "https://www.ogis.org/basemap/fonts/{fontstack}/{range}.pbf",
  "sprite": "https://www.ogis.org/basemap/sprite"
}
```

Use `https://www.ogis.org/basemap/sprite-light` for the light sprite set.

## Building and remixing

The build stages both icon palettes, runs one Docker recompose, builds four sprites, generates both styles with [`scripts/style.js`](scripts/style.js), publishes both styles and icon trees, merges the font stacks referenced by either style, and assembles the site:

```bash
./scripts/build.sh
```

- **Map theme** — [`themes/dark/theme.json`](themes/dark/theme.json) holds the ordered dark colour rules and tokens; the engine lives in [`scripts/lib/theme.js`](scripts/lib/theme.js) and [`scripts/lib/colour.js`](scripts/lib/colour.js). Light deliberately leaves the upstream layer tree untouched. See [themes/README.md](themes/README.md) for the schema.
- **Icon palettes** — the root [`palette.json`](palette.json) is the light identity palette; [`themes/dark/palette.json`](themes/dark/palette.json) is the contrast-tuned dark palette. They recolour the primary fill of selected POI SVGs before the sprites are built.
- **Vendored style** — edit the layer styles under `vendor/openmaptiles/layers/*/style.json` for cartographic changes. The mirror is generated, so reapply local edits after `npm run upstream:sync`.

> [!NOTE]
> `vendor/openmaptiles/` is a pristine mirror of upstream `master`; `npm run upstream:sync` replaces it, `npm run upstream:verify` checks it offline and `npm run upstream:check` compares the locked commit with upstream. Provenance is in [`vendor/openmaptiles.lock.json`](vendor/openmaptiles.lock.json); see [vendor/README.md](vendor/README.md) for the mirrored paths. Syncing source does not rebuild the published styles — run `./scripts/build.sh` afterwards. Both workflows run `npm run upstream:verify` after `npm test`.

To preview palette changes without a build, open the [demo](https://www.ogis.org/basemap/) or use a local build, choose **Dark** or **Light**, turn on **Inspect POIs**, click a POI and change its role colour. Every icon in the role updates live; **Export palette** downloads a `palette.json` for the active palette. Copy a light export into the root `palette.json` or a dark export into `themes/dark/palette.json` before running the full build.

To rebuild only the deployable site after app or palette-data changes that do not need new map artefacts, run `npm run site:build`; use `npm run dev` for a live preview at <http://127.0.0.1:11100/basemap/>. See [docs/3.remixing.md](docs/3.remixing.md), [docs/5.palette.md](docs/5.palette.md) and [docs/6.site.md](docs/6.site.md).
